# Задания по химии: дополнение уравнений реакций

Сайт для учеников: учитель загружает реакции, составляет из них задания, ученики дописывают недостающие
вещества и расставляют коэффициенты, сайт проверяет ответы автоматически.

Стек: Python 3.10+, Django 5.2, PostgreSQL. Внешних сервисов и CDN нет: сайт работает и в школьной сети с ограничениями.

## Что умеет

**Ученики и вход**
- Классы; список учеников вставляется текстом («Фамилия Имя» по строкам), логины (`ivanov.i`, можно с префиксом `10a.ivanov.i`) и пароли создаются автоматически.
- Пароли показываются один раз: таблица, CSV и печать карточек для разрезания. Потом можно только выдать новые (одному ученику, отмеченным или всему классу).
- Можно закрыть ученику вход, перевести его в другой класс или удалить.

**База реакций**
- Загрузка списком (текстом или файлом .txt) с предварительной проверкой каждой строки:
  - уравнено ли уравнение (по элементам и по заряду для ионных уравнений);
  - если не уравнено или коэффициенты не указаны — предлагаются варианты наименьших целых коэффициентов;
  - если коэффициенты можно сократить — предлагается сокращённый вариант;
  - если уравнение можно уравнять несколькими независимыми способами (типично для некоторых ОВР) — показываются варианты, и учитель выбирает сам;
  - поиск дубликатов в базе и внутри загружаемого списка: порядок веществ не важен, пояснения к веществам и условия важны (`HNO3(конц.)` и `HNO3(разб.)`, `=(t)` и `=` — разные реакции).
- Тэги для группировки (у реакции может быть несколько; новые тэги создаются прямо при вводе, есть страница управления тэгами), поиск по формуле и тэгу.
- Правка реакции одной строкой: панель вставки спецсимволов (→, ⇄, ↑, ↓, ·, условия над/под стрелкой, заряд), инструкция по записи и живой предпросмотр с проверкой баланса.

**Задания**
- Задание состоит из реакций базы; одна реакция может входить в несколько заданий, все настройки показа хранятся в задании.
- Что показывать — на уровне задания и отдельно для каждой реакции (строка «Ученик видит» обновляется сразу, до сохранения): реагенты, продукты, число недостающих веществ, «прятать воду». Каждое вещество можно отдельно показать или скрыть (переключатель авто → показать → скрыть).
- «Прятать воду»: вода не показывается, ученик сам решает, нужна ли она и с какой стороны.
- Проверка на неоднозначность: сайт находит в базе другие реакции, подходящие под то, что видит ученик (например, `Cu + HNO3` без пояснения), и до публикации просит решить, считать ли их тоже правильными ответами.
- Сроки (открыть с, сдать до, принимать ли позже), предпросмотр «как видит ученик», копирование задания.

**Выполнение и проверка**
- Ученик дописывает вещества (фиксированное число полей, если число веществ показано, иначе — сколько нужно) и расставляет коэффициенты; есть черновик и предпросмотр формулы с индексами.
- Автопроверка: 1 балл — верно; ½ балла (отключается) — вещества верны, коэффициенты нет; 0 — неверный набор веществ. Отдельно распознаётся ошибка «с водой».
- Показ результатов: сразу, с указанной даты или после подтверждения учителем (всем сразу или отдельным ученикам). По желанию — с правильными ответами.
- Апелляции по каждой реакции; учитель отвечает, может поставить оценку вручную или одной кнопкой «считать такой ответ правильным» — ответ ученика добавляется в базу как допустимый вариант, и все работы перепроверяются.
- «Перепроверить работы» после исправления реакции или настроек; ручные оценки учителя при этом сохраняются.
- Таблица результатов класса, выгрузка в CSV (открывается в Excel).

## Формат загрузки реакций

Одна реакция на строке:

```
# строки с # — комментарии
2H2 + O2 = 2H2O
Al + O2 → Al2O3                               # коэффициенты подберутся
KClO3 =^(t)_(MnO2) KCl + O2↑                  # t над стрелкой, MnO2 под стрелкой
Cu + HNO3(конц.) → Cu(NO3)2 + NO2↑ + H2O      # пояснение к веществу
NH4Cl =(t) NH3↑ + HCl↑                        # условие (t) — над стрелкой по умолчанию
2NH3 + H2SO4 = (NH4)2SO4                      # скобки в формуле не путаются с условиями
CuSO4·5H2O =(t) CuSO4 + 5H2O                  # кристаллогидрат (можно CuSO4*5H2O)
Fe3+ + 3OH- = Fe(OH)3↓                        # ионы
N2 + 3H2 ⇄^(t°, p)_(cat) 2NH3                  # обратимая
```

- Стрелка: `=`, `→`, `->`, `⟶`; обратимая — `⇄`, `⇌`, `<=>`.
- Условия — в скобках сразу после стрелки: `(…)` или `^(…)` — над, `_(…)` — под.
- Индексы в подписях (условиях и пояснениях): `_(…)` — нижний, `^(…)` — верхний, можно вкладывать: `→_(HCl_((aq.)))` — под стрелкой HCl с нижним индексом (aq.), градус — символ `°` или `^\circ`: `=^(t^\circ)` — t°.
- Пояснение — в скобках сразу после формулы: `(г)`, `(тв)`, `(р-р)`, `(конц.)`, `(aq)`… Знаки `↑`/`↓` выводятся, но на сравнение не влияют.
- Заряды: однозначно — `SO4^2-`, `SO4{2-}`, `SO₄²⁻`. Сокращённо тоже понимается: `NH4+`, `OH-`, `Fe3+` (одноатомный ион), `SO42-` (последняя цифра — заряд). Электрон — `e`.
- Если в записи нет ни одного коэффициента, сайт подбирает их сам; если коэффициенты частично указаны, недостающие считаются равными 1.

## Запуск на своём компьютере (Windows)

Нужны Python 3.10+, Git и Docker Desktop (в нём работает PostgreSQL).

```bash
git clone https://github.com/UnWaDo/chem-tasks-site.git
```
```bash
cd chem-tasks-site
```
```bash
docker compose up -d
```
```bash
python -m venv .venv
```
```bash
.venv\Scripts\pip install -r requirements.txt
```
```bash
.venv\Scripts\python manage.py migrate
```
```bash
.venv\Scripts\python manage.py createsuperuser
```
```bash
.venv\Scripts\python manage.py runserver
```

`docker compose up -d` запускает PostgreSQL 16 в контейнере `tasks-site-postgres-1`: порт 5432 только на этом компьютере,
база, пользователь и пароль — `chem`. Эти значения уже прописаны по умолчанию в `config/settings.py`, так что `.env` локально не нужен.
Данные хранятся в томе Docker `tasks-site_pgdata` и переживают перезапуск. Остановить базу — `docker compose stop`.

Откройте http://127.0.0.1:8000 и войдите под созданным пользователем — он и есть учитель
(учителем считается любой пользователь с флагом «персонал», `is_staff`).
Для быстрого знакомства можно загрузить демо-данные (только локально!): `.venv\Scripts\python manage.py demo_data`
— логины и пароли написаны в начале файла `accounts/management/commands/demo_data.py`.

Тесты (нужна запущенная база; тестовая база создаётся и удаляется сама): `.venv\Scripts\python manage.py test chem.tests assignments`

## Системные требования и выбор хостинга

Нагрузка у сайта маленькая: даже если класс из 30 человек одновременно сдаёт работу — это десятки лёгких запросов.
База данных — PostgreSQL, она ставится на тот же сервер.

| Ресурс | Минимум | Комфортно |
|---|---|---|
| Процессор | 1 vCPU | 1–2 vCPU |
| Память | 1 ГБ (+ swap 1 ГБ) | 2 ГБ |
| Диск | 10 ГБ SSD | 15–20 ГБ SSD |
| ОС | Ubuntu 22.04/24.04 или Debian 12 | Ubuntu 24.04 |
| Python | 3.10+ | 3.12 |
| PostgreSQL | 15+ (нужна локаль ICU) | 16 (входит в Ubuntu 24.04) |

Сайт (2 процесса gunicorn) занимает около 100–150 МБ памяти, PostgreSQL с настройками по умолчанию — 100–200 МБ,
nginx — ~10 МБ. Самый младший тариф VPS (1 ядро / 1 ГБ / 10 ГБ) справится, но с запасом — тариф с 2 ГБ.
Что ещё понадобится:
- домен (или поддомен школьного сайта) — нужен для HTTPS; без HTTPS пароли идут по сети открытым текстом;
- бесплатный сертификат Let's Encrypt (certbot ставит его за пару минут).

Виртуальный хостинг (через Passenger, есть `passenger_wsgi.py`) подойдёт, только если он даёт базу PostgreSQL 15+;
чаще там бывает лишь MySQL, поэтому для этого проекта лучше VPS.

## Развёртывание на VPS (Ubuntu 24.04)

Ниже `chem.example.ru` — ваш домен (его A-запись должна указывать на IP сервера).

```bash
sudo apt update && sudo apt install -y python3-venv nginx postgresql certbot python3-certbot-nginx
sudo adduser --system --group --home /srv/chem chem
sudo usermod -aG www-data chem
```

База данных. Придумайте пароль для базы и подставьте его вместо `ПАРОЛЬ` (и потом в `.env`).
Локаль ICU `ru-RU` нужна, чтобы поиск без учёта регистра и сортировка правильно работали с русскими буквами:

```bash
sudo -u postgres psql -c "CREATE ROLE chem LOGIN PASSWORD 'ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE chem OWNER chem TEMPLATE template0 ENCODING 'UTF8' LOCALE_PROVIDER icu ICU_LOCALE 'ru-RU' LOCALE 'C.UTF-8';"
```

Скопируйте папку проекта в `/srv/chem/app` (через `git clone`, `scp` или `rsync`; папку `.venv` копировать не нужно), затем:

```bash
sudo chown -R chem:chem /srv/chem
sudo -u chem -s
cd /srv/chem/app
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env        # SECRET_KEY, домен, POSTGRES_PASSWORD; DJANGO_DEBUG=0
.venv/bin/python manage.py migrate
.venv/bin/python manage.py collectstatic --noinput
.venv/bin/python manage.py createsuperuser
exit
```

Сервис и веб-сервер:

```bash
sudo cp /srv/chem/app/deploy/chem.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now chem
sudo cp /srv/chem/app/deploy/nginx-chem.conf /etc/nginx/sites-available/chem   # поправьте server_name
sudo ln -s /etc/nginx/sites-available/chem /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d chem.example.ru      # HTTPS и автоматическое продление
```

Резервные копии (`pg_dump` раз в сутки, хранятся 30 дней в `/srv/chem/backups`; иногда скачивайте их к себе):

```bash
sudo -u chem crontab -e
# добавить строку:
15 3 * * * /srv/chem/app/deploy/backup.sh
```

Восстановление из копии: `pg_restore --clean --if-exists -h 127.0.0.1 -U chem -d chem /srv/chem/backups/db-ГГГГ-ММ-ДД.dump`.

Обновление после изменения кода: загрузите новые файлы и выполните `deploy/update.sh`.

Если что-то не работает: `sudo journalctl -u chem -n 50` (ошибки сайта) и `sudo tail /var/log/nginx/error.log`.

## Перенос данных из старой базы SQLite

Если сайт уже работал на SQLite (файл `db.sqlite3`), данные переносятся штатными средствами Django.
Сначала создайте пустую базу PostgreSQL и выполните `migrate`, затем:

```bash
DJANGO_LEGACY_SQLITE=db.sqlite3 PYTHONUTF8=1 python manage.py dumpdata --database legacy --natural-foreign --natural-primary -e contenttypes -e auth.permission -e sessions -e admin.logentry -o dump.json
PYTHONUTF8=1 python manage.py loaddata dump.json
```

`PYTHONUTF8=1` нужен на Windows, иначе файл запишется не в UTF-8. Пароли учеников переносятся; сессии нет,
поэтому всем нужно будет войти заново. После проверки файл `dump.json` удалите — в нём персональные данные.

## Структура проекта

```
chem/            разбор формул и уравнений, уравнивание, проверка ответов (без Django, с тестами)
accounts/        классы, ученики, генерация логинов и паролей
reactions/       база реакций, импорт и проверка
assignments/     задания, настройки показа, работы учеников, проверка, апелляции
templates/       страницы
static/          стили и скрипты
deploy/          конфигурация для сервера (systemd, nginx, резервные копии)
docker-compose.yml  PostgreSQL для локальной разработки
docs/olympiad/   проект будущего блока олимпиадных задач
tools/olympiad/  офлайн-инструменты для олимпиадного блока (на сервер не нужны)
AGENTS.md        инструкции для ИИ-агентов, работающих с кодом
```

Образцы олимпиадных задач (`docs/olympiad/samples/`) в репозиторий не входят: публиковать тексты заданий в интернете
без согласия правообладателей нельзя.

Встроенная админка Django доступна по адресу `/admin/` — на случай, если что-то нужно поправить вручную.
