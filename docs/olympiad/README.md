# Олимпиадные задачи: источники, требования к разбору, схема хранения

Проектный документ для блока олимпиадных задач (сначала химия, потом другие предметы). Основан на
разборе 74 PDF с [olimpiada.ru/activity/76/tasks](https://olimpiada.ru/activity/76/tasks/2025)
(2015–2025, 7–11 классы, все этапы ВсОШ), прототипе парсера и ручной доводке 13 задач до полной структуры.

Что лежит рядом:

| Путь | Что это |
|---|---|
| `docs/olympiad/samples/*.json` | 6 пакетов в формате `olymp-bundle/1`, 13 задач разных типов: условие, вопросы, ключи, баллы, решение |
| `docs/olympiad/samples/assets/` | вырезки рисунков из PDF, на которые ссылаются образцы |
| `docs/olympiad/samples/preview.html` | как образцы выглядят на сайте: поля ввода, решения под спойлером (генерируется) |
| `docs/olympiad/samples/print.html` | сборник для печати: A4, пустые бланки как в оригинале, ответы и решения в конце (генерируется) |
| `tools/olympiad/render.py` | отрисовка блоков в HTML для страницы и для печати; только stdlib и `chem/` |
| `tools/olympiad/check_samples.py` | проверка образцов по схеме, ключей, бланков и индексов; собирает обе страницы |
| `tools/olympiad/parse_pdf.py` | прототип разбора PDF → черновик (этап A); офлайн, нужен PyMuPDF |

```bash
python tools/olympiad/check_samples.py
```

Папка `samples/` в Git не входит (см. «Права» ниже): образцы хранятся только локально.

## Коротко

- **Сканов почти нет, но «просто вытащить текст» не работает.** У 73 из 74 файлов есть текстовый слой. Теряются: индексы
  (H₂SO₄ превращается в «H2SO4» — индекс виден только по кеглю и сдвигу строки), символы шрифта Symbol (ν, ω, ×, →, °:
  1307 символов в выборке), формулы-объекты Word (дроби разваливаются), подписи в схемах ChemDraw (там текст переведён в
  кривые и не извлекается вообще), структура таблиц.
- **Разметка задач различается по источникам сильнее, чем по классам.** Есть четыре устойчивых формата: Москва (ЦПМ) —
  «тест» с номерами полей ответа; муниципальные этапы регионов — 4–5 задач свободной формы, иногда два варианта на
  альбомном листе; региональный и заключительный — сборники «Задача 9-1» с авторами и «Системой оценивания»;
  практические туры — без единого ключа. По классам меняется *содержание*: 7–9 — неорганика и закрытые ответы,
  10–11 — органические схемы, структуры, физхимия с формулами.
- **Полностью автоматический импорт нереалистичен; нужен конвейер «черновик → проверка учителем → публикация».**
  Прототип на 74 файлах нашёл 527 задач, 467 таблиц, 718 рисунков и 416 уравнений (399 уравнены). Остаток —
  схемы-картинки, формулы-объекты, битые файлы — человек доводит за минуты, видя рядом вырезку из PDF.
- **Схема:** реляционная обвязка (олимпиада → тур → задача → вопросы) + содержимое задачи в JSON-блоках с разметкой,
  совместимой с текущим `chem/` (`_(…)`, `^(…)`, формат строк реакций). Цепочки превращений хранятся одновременно
  вырезкой (как в оригинале) и графом (узлы, стрелки, условия, ответы по узлам).
- **Проверка на образцах прошла:** 13 задач, 178 блоков, все 38 уравнений разобраны существующим `parse_equation`
  (включая шаблоны с неизвестными `{А}`), 20 вопросов проверяются автоматически по ключу, неразобранных фрагментов нет.
  Из одних и тех же данных собираются страница сайта с полями ввода и сборник для печати с пустыми бланками.
  Попутно проверка нашла ошибку в официальном решении (СПб, 9 кл., II вариант: `2HClO4 + Zn = ZnSO4 + H2↑` — так в PDF).
- **Права.** В московских файлах ЦПМ указано, что публиковать задания в интернете без письменного согласия нельзя.
  Банк должен быть закрытым (только для вошедших пользователей школы) и всегда хранить ссылку на источник.

## 1. Источник: olimpiada.ru

**Адреса.** `https://olimpiada.ru/activity/76/tasks/<год>?class=<7…11>`, где год — начало учебного года
(2025 → 2025/26). Архив с 2005 года. Страница в cp1251.

**Структура страницы:** этапы (`<h3>`: школьный, муниципальный, региональный, заключительный, пригласительный) →
регионы (`<div reg=… rname="…">`, у региона и финала региона нет) → туры (`<h4>`: «Теоретический тур»,
«Практический тур» или без тура) → ссылки «Задания», «Решения», «Критерии», «Задания и критерии»,
«Справочные материалы», «Видеоразбор».

**Где лежат файлы:** `tasks.olimpiada.ru/upload/files/tasks/76/<год>/…` (регионы, региональный и заключительный
этапы) и `всош.цпм.рф/upload/files/Arhive_tasks/…` (Москва: школьный, муниципальный, пригласительный). Видео —
rutube/vk, это просто ссылки.

**Имена файлов:** `<вид>-chem-<классы>-<тур>-<этап>-<регион>-<гг>-<гг>.pdf`:

| Часть | Значения |
|---|---|
| вид | `tasks` задания, `sol`/`ans` решения, `krit` критерии, `taskskrit` всё в одном |
| классы | `9`, `7-8`, `9-11`, `10-11` — файл может относиться к нескольким классам |
| тур | `teor`, `prak`, `teor1`, `teor2` или нет |
| этап | `sch`, `mun`, `reg`/`region`, `final`, `prigl` |
| регион | `msk`, `spb`, `perm`, `kursk`… |

Имена непоследовательны: `region` и `reg` в одном комплекте, в 2015 году другой порядок
(`tasks-chem-9-msk-mun-15-6`). Поэтому метаданные берём из структуры страницы, а имя — только для сверки.

**Объём и дубли.** На 2025/26 опубликован только муниципальный этап: для 9 класса 1 московский комплект, 8
практических и 24 теоретических региональных. Регионы часто решают одни и те же задания (одна методическая комиссия
на несколько регионов): у Курской области и Санкт-Петербурга задания 9 и 11 классов совпадают на 97–99 %, отличаются
только шапки, а файлы разные (у Курска 10 класс вообще скан). Дубли нужно ловить по нормализованному тексту без
шапок, а не по хэшу файла.

| Схемы Word: подписи — текстовые надписи, стрелки — картинки | Москва 10 кл. | вырезка + подписи для поиска; граф — вручную или полуавтоматически |

## 3. Требования к разбору

### 3.1. Общие для всех классов

1. **Метаданные** — со страницы olimpiada.ru (год, этап, регион, тур, классы, вид файла), имя файла — для сверки.
2. **Склейка комплекта:** задания ↔ решения ↔ критерии по номеру задачи (`9-1`, `7`, `№2` + вариант). Условие в решениях
   обычно повторяется — его используем для проверки, а не как второй экземпляр.
3. **Очистка вёрстки:** колонтитулы (повторяются у края на половине страниц, но не «Задача N»), номера страниц,
   переносы (`смешива-` + `ющуюся`), обтекание рисунков, колонки на альбомных листах.
4. **Индексы и заряды** по геометрии → разметка `_(…)`/`^(…)` (уже понимает `chem.equation.markup_html`).
5. **Символы:** перекодировка Symbol-PUA, математический курсив Cambria → обычные буквы, кириллица → латиница внутри формул.
6. **Таблицы:** границы по линейкам, текст ячейки — по фрагментам строки (иначе соседние ячейки склеиваются),
   объединённые ячейки → `colspan`/`rowspan`; картинка в ячейке — вырезать всю ячейку (у структур Льюиса буквы —
   текст, а черточки — графика; вырезка только графики теряет буквы).
7. **Рисунки:** растр — вырезать; вектор — кластер графики **вместе с подписями-текстом между фрагментами**
   (иначе схема СПб распадается на три куска без подписей); ChemDraw — целиком. Подложки заголовков и рамки (1–4
   простых прямоугольника) — не рисунки.
8. **Формулы-объекты** → вырезка-картинка + пометка «набрать вручную».
9. **Уравнения:** найти строки-реакции, нормализовать (см. список выше), разобрать `parse_equation`, проверить баланс.
   Неуравненное уравнение в решении — повод показать его проверяющему: в выборке так находятся опечатки источника.
10. **Границы задач:** «Задача N», «Задача 9-1», «Решение задачи 9-1 (автор: …)», «№N», жирное «N.» в начале абзаца;
    разделы («Неорганическая химия»); классы «(для 9 и 10 классов)»/«(только для 9 класса)»; номера полей «(№7-8)»;
    названия задач; варианты «9 класс II вариант».
11. **Вопросы:** «1.», «7.», «10)», «3а» — вопросы; «1) Вещества X, 2–4 содержат…» — условия-список. Различаются
    жирностью номера и стилем документа, поэтому это место всегда проверяет человек.
12. **Ответы и баллы:** «Ответ:», «За верный ответ N баллов», «Система оценивания» / «Разбалловка» /
    «Рекомендации к оцениванию», «ИТОГО: N баллов», «засчитывается также», «принимать диапазон от … до …»,
    «за каждый неверный ответ вычитается …».
13. **Детекторы брака:** скан, битая кодировка, формулы-объекты, текст в кривых → предупреждения в отчёте импорта.
14. **Дубли:** хэш нормализованного текста условия без шапок, поиск похожих при импорте.
15. **Всё автоматическое — черновик.** Публикация только после проверки учителем, рядом с вырезкой страницы.

### 3.2. По классам

**7–8 классы** (только школьный и муниципальный этапы; у Москвы общий файл `7-8`)
- Закрытые ответы: выбор, соответствие, число, формула. Картинки в вариантах ответа (лабораторная посуда, 8 рисунков
  на странице для соответствия), таблицы-соответствия.
- Уравнения простые: 21 из 21 разобраны и уравнены.
- Нужно: картинки в вариантах ответа, `choice`/`match`, числа с допуском. Сложность разбора низкая.

**9 класс**
- Неорганика: «определите вещества A–F», цепочки превращений с буквами и номерами (ветвящиеся, не только линейные),
  расчёты, электронные формулы (вектор в таблице), рисунки приборов, термохимия.
- Практический тур — распознавание растворов в пробирках; ключ зависит от площадки.
- Нужно: шаблоны уравнений с неизвестными (`{А}(р-р) + {Б}(р-р) → BaSO4 + {В}(р-р)`), схемы как граф, поля-формулы
  с альтернативами (`XeF4` / `F4Xe`), варианты I/II, разбалловка с долями балла (0,25).

**10 класс**
- Добавляется органика (гомологи, общие формулы `CnH2n`), схемы Word с подписями-текстом (в т.ч. циклы), электролиз,
  условия над и под стрелкой, агрегатные состояния, формулы-объекты в решениях.
- Нужно: условия на стрелках, пояснения `(р-р)`, `(тв.)`, `(газ)`; общие формулы с переменными индексами (пока как
  текст с разметкой); структурные формулы — картинкой, при желании со SMILES.

**11 класс**
- Синтетические схемы ChemDraw (текст в кривых: 32 рисунка в файлах 11 класса и ещё 80 в сборном II туре финала), стереохимия (Ньюмен, Фишер), физхимия
  (кинетика, термодинамика — формулы-объекты), кристаллохимия, таблицы данных, графики.
- Нужно: схема синтеза как граф с узлами-структурами без букв, реагентами-буквами на стрелках, многостадийными
  условиями «1) … 2) …», несколькими продуктами; подмножество TeX для формул; ответ, зависящий от выбора ученика
  («выберите температуру от 310 до 350 К…»); структуры в ответах — пока ручная проверка по критериям.

**Сборные туры 9–11** (II тур заключительного этапа)
- Один файл на три класса, задачи сгруппированы по разделам, у каждой свой набор классов, нумерация в разделе
  начинается заново. Решение — 73 страницы, есть список литературы.
- Нужно: классы задачи — множество, раздел, литература.

### 3.3. По формату (влияет на автопроверку больше, чем класс)

| Формат | Где | Автопроверка |
|---|---|---|
| «Тест» с номерами полей (`Задача 7 (№7–8)`) | Москва, школьный и муниципальный | почти полностью: выбор, соответствие, формулы, числа |
| Свободная форма, 4–5 задач, критерии с долями балла | муниципальные этапы регионов | частично: уравнения и вещества; остальное по критериям |
| Сборник «Задача 9-1», авторы, «Система оценивания» | региональный, заключительный | в основном ручная, по критериям |
| Практический тур | все этапы | только критерии; ключ задаёт площадка |

## 4. Схема хранения

### 4.1. Модели (новое приложение `olymp`)

Реляционная часть — для поиска, фильтров и прав; содержимое задачи — JSON-документ (раздел 4.2).

```python
class Olympiad(models.Model):            # «ВсОШ по химии», «Московская олимпиада»…
    subject = CharField(choices=…)       # chem, phys, bio… — задел на другие предметы
    name, short_name = CharField(), CharField()
    source_url = URLField(blank=True)    # https://olimpiada.ru/activity/76

class Contest(models.Model):             # одна работа: этап + регион + тур + год
    olympiad = ForeignKey(Olympiad)
    season = CharField()                 # "2025/26"; year_start = PositiveSmallIntegerField()
    stage = CharField(choices=school/municipal/regional/final/invitational/other)
    region = CharField(blank=True)       # пусто для регионального и финала
    tour = CharField(blank=True)         # theory, practice, theory1, theory2
    grades = ArrayField(PositiveSmallIntegerField())   # [9] или [9, 10, 11]
    max_score, duration_min = DecimalField(null=True), PositiveSmallIntegerField(null=True)
    format = CharField(choices=closed-answers/long-answers/practical)
    source_page = URLField(blank=True)

class SourceFile(models.Model):          # исходный PDF и что с ним сделал импорт
    contest = ForeignKey(Contest, null=True)
    kind = CharField(choices=tasks/solutions/criteria/tasks+criteria/reference)
    url = URLField(blank=True); file = FileField(upload_to="olymp/src/")
    sha256 = CharField(unique=True); pages = PositiveSmallIntegerField(); page_offset = SmallIntegerField(default=0)
    grades = ArrayField(...)
    parse_status = CharField(choices=new/parsed/review/done/failed)
    parser_version = CharField(); report = JSONField()   # статистика и предупреждения разбора

class Problem(models.Model):
    contest = ForeignKey(Contest, null=True)             # null — своя задача учителя
    origin = CharField(choices=official/teacher); owner = ForeignKey(User, null=True)
    number = CharField()                 # "9-1", "7", "2"
    ext_numbers = CharField(blank=True)  # "7–8" — номера полей ответа в московском формате
    section = CharField(blank=True)      # "Неорганическая химия"
    variant = CharField(blank=True); slot = CharField(blank=True)   # вариант II задачи 2
    grades = ArrayField(PositiveSmallIntegerField())
    title, authors = CharField(blank=True), CharField(blank=True)
    max_score = DecimalField(null=True)
    statement = JSONField()              # {"v": 1, "blocks": [...]}
    solution = JSONField(default=dict)
    practical = JSONField(default=dict)  # реактивы, оборудование, образцы
    references = JSONField(default=list)
    topics = ManyToManyField(Topic)      # рубрикатор: раздел курса → тема
    status = CharField(choices=draft/review/published)
    visibility = CharField(choices=private/school)       # публичного доступа нет
    content_hash = CharField(db_index=True); duplicate_of = ForeignKey("self", null=True)
    src = JSONField(default=dict)        # {"<source id>": [страницы]} — для показа оригинала
    revision = PositiveIntegerField(default=1)

class Question(models.Model):            # единица ответа и оценивания
    problem = ForeignKey(Problem, related_name="questions")
    label = CharField()                  # "1", "3а", "16"; на него ссылаются блоки q/answer
    position = PositiveSmallIntegerField()
    points = DecimalField()
    answer = JSONField()                 # ключ и правила проверки (раздел 4.3)
    rubric = JSONField(default=list)     # [{"text": …, "points": …}]
    manual_check = BooleanField(default=False)

class Asset(models.Model):               # картинки и вырезки
    problem = ForeignKey(Problem, null=True); key = CharField()   # "a1" — id внутри задачи
    file = FileField(upload_to="olymp/a/")   # имя по sha256
    kind = CharField(choices=drawing/scheme/structure/photo/math/page-crop)
    width, height = PositiveIntegerField(), PositiveIntegerField()  # из импорта: Pillow не ставим
    alt = CharField(blank=True); text_outlined = BooleanField(default=False)
    src = JSONField(default=dict)        # {"source": id, "page": 7, "bbox": [...]}
```

Почему так:
- **Классы — массив, а не одно число**: файлы `7-8`, задачи «для 9 и 10 классов». `grades__contains=[9]` в PostgreSQL.
- **Вопросы — отдельные строки**, а не часть JSON: на них ссылаются баллы, апелляции и будущие ответы учеников
  (по аналогии с `AssignmentItem`/`Answer`). Текст вопроса остаётся в потоке условия (блок `q`), чтобы сохранить
  порядок «текст — вопрос 1 — текст — вопрос 2», как в региональных задачах.
- **Содержимое — JSON с версией `v`**: можно валидировать, рисовать шаблонами Django без JS-библиотек и мигрировать.
- **Вариант и слот**: `slot="2"` объединяет варианты I и II одной задачи — удобно для подбора и статистики.
- **Своя задача учителя** — та же модель с `origin=teacher` и `owner`, без `contest`.

Файлы: в проекте пока нет `MEDIA_ROOT`. Понадобятся `MEDIA_ROOT`/`MEDIA_URL`, раздача через nginx (`location /media/`)
только для вошедших (например, `X-Accel-Redirect` из Django-представления, раз банк закрытый) и добавление `media/`
в `deploy/backup.sh`. Объём небольшой: прототип сделал 671 уникальную вырезку с 643 страниц при 170 dpi — 22 МБ.

### 4.2. Содержимое задачи: блоки

`{"v": 1, "blocks": [ … ]}`. Тип блока — поле `t`.

| `t` | Поля | Для чего |
|---|---|---|
| `p` | `text` | абзац с разметкой |
| `h` | `text` | подзаголовок внутри задачи |
| `list` | `style` (`1)`, `а)`, `•`), `items`: строки или `{blocks}` | условия-списки «1) Вещества X…» |
| `q` | `q` (метка вопроса), `text` | формулировка вопроса в потоке условия |
| `answer` | `q`, `form` (раздел 4.3) | бланк ответа: как он выглядит в оригинале и какие поля у него на сайте |
| `choices` | `id` или `q`, `options: [{k, text, asset?}]` | варианты выбора; один набор может обслуживать несколько вопросов (№10–13) |
| `match` | `q`, `left`, `right` (элементы с `text` или `asset`) | задания на соответствие |
| `figure` | `asset`, `caption`, `float` | рисунок |
| `table` | `rows: [[{text, asset?, colspan?, rowspan?, h?}]]`, `head_rows`, `notes` | таблицы данных, сноски |
| `eq` | `text` (формат строк реакций сайта), `template?`, `n?`, `comment?`, `review?` + `src` | уравнение реакции; `template` — с неизвестными `{А}`; `review` — ошибка источника со ссылкой на страницу PDF |
| `scheme` | `asset`, `nodes`, `edges`, `layout?`, `legend?`, `render?` | цепочка превращений (раздел 4.4) |
| `math` | `tex` (подмножество), `label?`, `asset?` | выключная формула |
| `note` | `kind` (info / footnote / review), `title?`, `text` или `blocks` | «Дополнительная информация», справочные данные; `review` — заметка проверяющего, в печать не идёт |
| `raw` | `reason`, `text`, `asset?`, `src` | не разобранный фрагмент: формула-объект, скан, битый текст. Публикация запрещена, пока такие блоки есть |

**Разметка внутри текста:**
- `_(…)`, `^(…)` — индекс и верхний индекс любой длины: `t_(1/2)`, `S_(N)2`, `мин^(−1)`, `Fe_(2.77)N`;
- короткая запись: `_2` — **только цифры**; `_C`, `_Br`, `_a`, `_n` — одна буква и следующие за ней строчные;
  `^2+`, `^+`, `^3` — цифры со знаком. Так `P_2O_5`, `X_1−X_6`, `X_nY`, `ω_C` читаются однозначно;
- `t^o` → `t°` (как сейчас на сайте);
- `**X**` — полужирный (обозначения веществ, номера вопросов, подписи бланков — как в оригинале), `*Lytta vesicatoria*` — курсив;
- `{X1}` — ссылка на неизвестное вещество (в уравнениях и на стрелках схем);
- `$…$` — строчная формула в подмножестве TeX.

Короткая запись в существующем `markup_html` захватывает всю цепочку букв и цифр (`P_2O_5` → P<sub>2O</sub>5,
`X_nY` → X<sub>nY</sub>) — так на первой версии предпросмотра и выходили неверные индексы. Ядро `chem` я не менял:
олимпиадный текст перед `markup_html` приводит короткую запись к скобочной (`olymp_markup` в `tools/olympiad/render.py`).
При переносе на сайт это правило стоит закрепить в `chem/` с тестами. Проверка образцов дополнительно ищет в готовом
HTML «подозрительные» индексы — цифры вперемешку с буквами («2O», «1−X») или строчную перед заглавной («nY»).

Цифры в тексте задачи **не** превращаются в индексы автоматически (`auto_sub=False`): в прозе встречаются «атом C2»,
«pH 7», «10.00%». Индексы приходят явными: из PDF — по геометрии, у учителя — из редактора.
Внутри блоков `eq` действует привычный формат строк реакций: `KClO3 =^(t)_(MnO2) KCl + O2↑`.

**Подмножество TeX** без внешних библиотек (CDN запрещены): `\frac`, `_{}`, `^{}`, `\left( … \right)`, `\ln`, `\exp`,
`\mathrm`, `\text`, греческие буквы, `\cdot`, `\approx`. Рисуется в HTML+CSS (`math_html` в `render.py`). В PDF такие
формулы — объекты Equation и при извлечении текста разваливаются, поэтому их набирают при проверке; в образцах
так набраны формулы решений 11-3 и задачи 5 финала.

### 4.3. Ответы и проверка

`Question.answer` — вид ответа и ключ. Для каждого вида проверщик в образцах проверяет, что эталон даёт полный балл,
а неверный ответ — меньше.

| `kind` | Ключ | Пример из выборки |
|---|---|---|
| `choice` | `key`, `multi`, `options` (id набора), `scoring` (`per_correct`, `per_wrong`, `min`) | Москва 9, №10–13: +1 за верный, −1 за неверный |
| `match` | `key: {"А": "3", …}`, `scoring.per_item` | Москва 9, №9 |
| `number` | `value`, `tol` / `tol_rel` / `range`, `integer`, `unit` | «сумма коэффициентов = 8»; «принимать от 9 до 10» |
| `fields` | `fields: [{k, type: formula/element/number/text, accept: [...], points}]` | X/A/B; «198, или 118, или 154»; «засчитывается также 156» |
| `equations` | `accept` (строки реакций), `per_item` | проверка существующим `chem.grading.grade`: вещества + коэффициенты, ½ балла |
| `expression` | `inputs` (с диапазоном), `expr`, `tol_rel` | 11-3: ответ зависит от выбранной учеником температуры; ключ сверен с таблицей жюри (41 точка, отклонение ≤ 0,5 %) |
| `structures` | `nodes`, `per_item`, `stereo` (узлы, где важна стереохимия) | 11-5: структуры A–O; N и O различаются только эндо/экзо |
| `manual` | — | длинные решения, практика |

Формулы сравниваются через `normalize_formula`, уравнения — через `chem.grading`. `rubric` хранит критерии жюри
текстом с баллами; у критерия может быть `auto`, если часть баллов считается машиной (например, «уравнения по 0,5,
без коэффициентов — 0,25»).

**Бланк ответа** (`answer.form`) хранится отдельно от ключа. Ключ отвечает на вопрос «что верно», бланк — «как это
выглядит»: на странице это поля ввода, в сборнике для печати — пустые клетки и линейки как в оригинале. Поле бланка
ссылается на вопрос и ключ (`{"q": "16", "k": "X1"}`), поэтому одна таблица может обслуживать несколько вопросов
(«3. Формула металла | ___», «4. Число электронов | ___»).

| `form.type` | Что внутри | Страница | Печать |
|---|---|---|---|
| `table` | `rows`: клетки-подписи `{text}` и клетки-поля `{input: {q?, k?}}`, `colspan` | поля в таблице; бланк «подписи сверху, поля снизу» (А…З, X1…X6) на узком экране выкладывается плиткой «подпись — поле» | таблица с пустыми клетками |
| `line` | `label` («Ответ.»), `unit?` | одно поле; у вопроса с выбором ответ отмечается прямо в списке вариантов | «Ответ. ________» |
| `lines` | `n` | многострочное поле | `n` линеек |
| `equations` | `n` | `n` строк для уравнений (дальше — ввод как в заданиях на уравнения) | нумерованные линейки |
| `structures` | `cells: [{k}]`, `box_mm` | рамка с кнопкой редактора структуры для каждого узла | пустые рамки с буквами |
| `space` | `height_mm?`, `note?` | поле для решения | место заданной высоты или ничего |

Вид поля задаётся ключом: формула, символ элемента, число, выбор (отметки с вариантами из общего набора), соответствие
(выпадающий список). `"print": false` — бланк только для сайта, когда в оригинале места для ответа нет (регион, финал:
участник пишет на отдельном листе).

Парсер распознаёт бланки сам: «Ответ» + таблица → `table` (подпись поля берётся из заголовка столбца, если поле в
столбце одно, иначе из подписи строки; номер вопроса — из подписей «10.», «5. Формула …»), «Ответ. ______» → `line`,
строки из подчёркиваний → `lines`, подряд идущие короткие «1) …» перед бланком → `choices`. На трёх московских
комплектах (9 и 10 классы 2025/26, 9 класс 2024/25) распознаны 49 бланков и 3 набора вариантов. Вопросы и подписи
полей совпали с оригиналом, кроме двух мест: лишнее пустое поле в шапке таблицы (9 кл. 2024/25, задача 2) и
пункты «1) V(CO2)», «2) M(смеси)» внутри одного вопроса №12 (10 кл., задача 8), которые парсер принял за номера
вопросов. Такие места видны при проверке: номер вопроса поля не совпадает с номерами задачи.

**Редактор структурных формул.** Подходит OpenChemLib JS (BSD-3): один файл ~1,1 МБ, кладётся в `static/` без CDN,
внутри редактор `CanvasEditor`, разбор SMILES и molfile, отрисовка в SVG и канонический код структуры
`getCanonizedIDCode`. Проверил на версии 9.25.1:
- разные записи одной молекулы (`C=CC(=O)OC` и `COC(=O)C=C`, ароматический и кекулевский фуран) дают один код;
- эндо- и экзо-аддукты N и O из 11-5, цис- и транс-бутен-2 различаются, а с `stripStereoInformation()` совпадают —
  значит, стереохимию можно требовать только там, где она оценивается (`stereo` в ключе).

Как это устроено: ученик рисует в редакторе, на сервер уходят molfile (для показа учителю и апелляций) и канонический
код; сервер сравнивает строки с кодами ключа. Ключ учитель рисует в том же редакторе или вставляет SMILES. Сервер
остаётся без RDKit и других зависимостей. Подделать код бессмысленно: чтобы отправить верный код, нужно знать верную
структуру. Структуры ученика на страницах учителя рисуются из molfile тем же редактором; готовый SVG от клиента не
сохраняем — это недоверенные данные. Альтернативы: JSME (BSD-3, около 2,5 МБ) — тоже годится, но без канонического
кода; Ketcher (Apache-2.0) — около 110 МБ, для школьного VPS тяжело.

### 4.4. Схемы превращений

Схема хранится дважды: **вырезкой** (`asset` — так, как задумал автор, включая структуры и стрелки любой формы) и
**графом** — для поиска, ключей по узлам, доступности и будущего интерактива («впишите вещества в схему»).

```json
{"t": "scheme", "asset": "a1", "layout": "cycle",
 "nodes": [{"id": "X1", "ref": "X_1", "answer": ["AlCl3"]},
           {"id": "MH2", "f": "MH2"},
           {"id": "ketoester", "given": "структура дана на схеме", "smiles": "COC(=O)C1CSCC1=O"},
           {"id": "B", "ref": "B", "hint": "ω_C = 55.8%", "smiles_answer": "C=CC(=O)OC"}],
 "edges": [{"from": ["X1"], "to": ["X2"], "above": "NaOH", "below": "избыток конц. р-ра"},
           {"from": ["H"], "to": ["I"], "above": "{B}", "below": "Py", "reagent_nodes": ["B"]},
           {"from": ["acoh"], "to": ["F"], "steps": [{"above": "Br_2", "below": "P(красн.)"}, {"above": "H_2O"}]},
           {"from": ["M"], "to": ["N", "O"], "above": "{E}", "below": "15 кбар"},
           {"from": ["X"], "to": ["1"], "n": 1}]}
```

Узел — неизвестное (`ref`), известная формула (`f`), текст (`text`) или данная структура (`given` + `smiles`);
`hint` — данные у узла (массовая доля, брутто-формула), `answer`/`smiles_answer` — ключ. Стрелка — откуда/куда
(списки: несколько продуктов), условия над/под, номер реакции `n`, многостадийные условия `steps`, вещества-реагенты
из схемы `reagent_nodes`. Автоматически граф строится только для простых Word-схем; для ChemDraw — вручную, но это
5–10 минут на схему.

- у узлов схемы — `given` (структура без буквы), `hint`, `highlight`; у стрелок — `steps`, `reagent_nodes`, `to` как список;
- общий набор вариантов (`choices.id`) для нескольких вопросов; `slot` для вариантов;
- вид ответа `expression`; раздел `practical`; бланки ответа `answer.form` с `print: false` для сайта;
- `references`, `page_offset`; `review` + `src` у уравнения (ошибка источника со ссылкой на место в PDF); заметки
  `note.kind = review`, которые не попадают в печать.

Чего схема пока сознательно не делает: графики и диаграммы (только картинкой), стереохимия в графе схемы
(только у ключа структуры), общие уравнения с переменными индексами (`2Fe_nN + 0.75nO2 = …` — пока формулой TeX).

## 6. Прототип разбора

`tools/olympiad/parse_pdf.py` — этап A: PDF → черновик в тех же блоках + вырезки + отчёт. Реализовано: колонтитулы,
колонки, склейка абзацев по медианному интервалу, индексы по геометрии, Symbol-PUA, таблицы по фрагментам строк,
кластеры рисунков с отсевом рамок и подложек, границы задач и вопросов по шаблонам из 3.1, разделы, классы, варианты,
баллы и «ИТОГО», распознавание и проверка уравнений через `chem`, бланки ответов и наборы вариантов, детекторы скана,
битой кодировки, формул-объектов и текста в кривых.

Вырезка рисунков:
- к рисунку присоединяются подписи рядом с ним, если они набраны другим шрифтом или мелким кеглем
  (Arial, Calibri в схемах против Times в тексте) и не начинаются от левого поля: так слова обтекающего текста не
  прилипают к схеме;
- короткие тонкие линии вне таблиц — стрелки схем, а не линейки (иначе схема СПб распадалась на куски);
- куски одной строки схемы сливаются, если стоят рядом в одной полосе;
- рамка подрезается так, чтобы не задевать строки основного текста сверху, снизу и сбоку — раньше в вырезку
  попадала строка над схемой (Москва 10, задача 10) и строка вопроса под схемой (11-5);
- картинка в ячейке таблицы вырезается всей ячейкой без метки «1)», с обрезкой белых полей: у электронных формул буквы —
  текст, а черточки — графика.

Склейка текста: дефис в конце строки сохраняется, если слово с дефисом встречается в документе или перенос стоит
перед заглавной буквой или после цифры («брутто-формулу», «Гелля-Фольгарда», «1,2-дизамещённым»); абзац,
разорванный границей страницы, склеивается.

На 74 файлах (12 минут; около 80 % времени — поиск таблиц в PyMuPDF, на страницах без линеек он пропускается):
527 задач в 67 файлах, 465 таблиц, 582 рисунка (55 — в ячейках таблиц; рисунков меньше, чем в первой версии,
потому что куски одной схемы теперь сливаются), 420 уравнений, из них 402 уравнены; бланки: 63 таблицы, 59 строк
«Ответ. ____», 3 блока линеек, 18 наборов вариантов. Предупреждение «ответ без бланка» (221) почти всё из файлов
решений, где «Ответ: …» — это ключ, а не бланк; при импорте решений такие строки надо разбирать в `Question.answer`.

Без задач остались 4 файла практического тура 2019 года (нет заголовков «Задача»), задания и критерии
практического тура Перми и скан Курска (детектор сработал). В файлах с битой кодировкой задачи нашлись — уцелели
заголовки «№1», но текст внутри всё равно нечитаем. Известные недоработки: внутренние пункты «1)», «2)» одного
вопроса иногда принимаются за номера вопросов, не склеиваются уравнения, перенесённые на следующую строку, общие
уравнения с переменными индексами (`Fe_nN`) не разбираются.

PyMuPDF под лицензией AGPL, поэтому инструмент остаётся офлайновым и на сервер не ставится. Если понадобится
встроить разбор в сайт, есть варианты pypdfium2 (Apache/BSD) + pdfminer.six (MIT), но на VPS с 1 vCPU разбор
PDF всё равно лучше не запускать.

## 7. Конвейер и план

1. **Импорт (офлайн).** `parse_pdf.py` по списку ссылок со страницы olimpiada.ru → пакет `olymp-bundle/1`
   (JSON + PNG) на комплект «задания + решения». Скан и битые файлы — OCR на компьютере учителя или ручной ввод.
2. **Загрузка пакета на сайт** — management-командой или формой учителя (zip). Задачи попадают в статус `draft`,
   ассеты — в `MEDIA_ROOT`, отчёт разбора — в `SourceFile.report`.
3. **Проверка учителем** — страница «черновик слева, вырезка страницы PDF справа»: правка блоков, разметка вопросов,
   ключей и баллов, граф схемы поверх вырезки, решение по `raw`-блокам. Публикация запрещена, пока есть `raw`
   и пока сумма баллов не сходится с `max_score` (по аналогии с `_publish` и неоднозначностями в заданиях).
4. **Банк задач** — поиск по году, этапу, региону, классу, разделу, теме, формуле (по `eq` и узлам схем), фильтр
   «с автопроверкой».
5. **Свои задачи** — тот же редактор блоков; уравнения вводятся привычными строками с живым предпросмотром, как на
   странице реакций.
6. **Связь с текущим сайтом** (по желанию): уравнения из решений → в базу реакций с тэгом источника → задания
   «дополни уравнение»; позже — олимпиадная задача как пункт задания с автопроверкой по `Question.answer`.

Порядок внедрения: модели и импорт пакета → просмотр задачи → редактор-проверка → банк с фильтрами → автопроверка
закрытых ответов. Начинать лучше с московских комплектов школьного и муниципального этапов: формат стабильный,
почти всё проверяется автоматически, и на них быстрее всего обкатать конвейер.

Открытые вопросы:
- Права на тексты: банк только для вошедших пользователей и ссылка на источник у каждой задачи — достаточно ли этого,
  или для московских комплектов нужно согласие ЦПМ.
- Будут ли ученики решать олимпиадные задачи на сайте (тогда нужны модели попыток по образцу `Submission`/`Answer`)
  или это банк для учителя и печати.
- Нужны ли другие предметы в ближайшее время: схема к этому готова (`Olympiad.subject`, блоки без химической
  специфики), но физике понадобится больше TeX и графики.
